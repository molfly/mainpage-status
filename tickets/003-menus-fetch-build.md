# 003. Меню обеденных мест: источники и сборка

Статус: done (механизм); open (живой прогон против VK)
Дата: 2026-09-17

## Задача

Разместить на странице меню мест, где обедаем. Первый источник — альбом ВК
(см. `docs/1.txt`). Фото достаются при сборке страницы, а не коммитятся в репозиторий.

## Решение

- `data/menusources.json` — реестр источников. Режимы:
  - `vk_album` — автоматически через VK API (`photos.get`), нужен токен `VK_TOKEN`;
  - `photos` — ручной список URL (запасной режим).
- `tools/fetch-menus.mjs` — качает фото в `site/assets/menus/<id>/` и генерирует
  `site/data/menus.js` (`window.MENUS`), чтобы страница работала и с `file://`.
  Сборка идемпотентна: каталог источника очищается перед закачкой.
  Запуск: `node tools/fetch-menus.mjs [sources.json] [site-dir]` (токен читается
  из окружения или `.env`).
- Страница: раздел «Меню» под колесом — место → сетка фото, клик открывает оригинал.
- `.github/workflows/build.yml` — сборка и деплой на GitHub Pages
  (push в main, ежедневно по расписанию, вручную).

## Настройка CI (одноразово)

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Secrets → **VK_TOKEN** (секрет репозитория).

## Токен VK

VK API требует токен даже для публичных альбомов. Подходит **service token**
приложения VK (читает публичные данные групп server-side): создаётся в
настройках standalone-приложения на dev.vk.com. Локально тот же токен кладётся
в `.env` (не коммитится).

## Ограничения / риски

- ~~VK недоступен из текущей сети~~ снято: проблема была в системном прокси
  `ge.molfly.me:4555` — напрямую VK доступен. Node fetch не использует
  `http_proxy`/`https_proxy`, так что скрипт ходит напрямую и локально работает.
  Проверено до границы авторизации: API отвечает `error_code 15` без токена.
- Логика разбора ответа VK API (`sizes` → максимальный размер) не проверена
  на живых данных — первый полный прогон после получения VK_TOKEN.
- VK может резать запросы с датацентровых IP; если CI-прогон упадёт — режим
  `photos` с ручными URL как fallback.
